# Перевести лендинг на сравнение «банк против банка»

Этот ExecPlan является живым документом и поддерживается по правилам `PLANS.md`. Разделы `Progress`, `Surprises & Discoveries`, `Decision Log` и `Outcomes & Retrospective` обновляются по мере выполнения.

## Purpose / Big Picture

После изменения пользователь выбирает два банка один раз и сразу видит карту всех уровней обоих банков. Уровни с подтверждёнными пересекающимися или близкими условиями входа образуют пары, каждый уровень показывается ровно один раз, а уровень без достаточно надёжного аналога остаётся отдельной строкой. Краткая карточка пары раскрывается в полное сравнение по всем существующим категориям.

## Surprises & Discoveries

- Observation: JSON уже сгруппирован как банк → уровни, поэтому менять сканер, схему данных или источник пользовательских фактов не требуется.
  Evidence: `build_payload()` возвращает элементы `{"bank": ..., "levels": [...]}`.
- Observation: число уровней заметно различается: от четырёх до восьми на банк, а часть условий входа не имеет подтверждённого числового порога.
  Evidence: текущий `output/comparison_data.json` содержит 38 уровней; `entry_match.eligible` бывает ложным.
- Observation: в `landing/sber_vs.py` уже есть незакоммиченные изменения оценки условий.
  Evidence: `git diff -- landing/sber_vs.py` показывает правки лимитов, карт Supreme и специальной иерархии Газпромбанка. Они должны быть сохранены.
- Observation: проектный Python и Node не содержат Playwright, а встроенный браузер не разрешает открывать локальный `file://` артефакт.
  Evidence: браузерный unittest пропущен с `Playwright is not installed`; встроенный браузер отклонил локальный URL по своей политике. Проверка компенсирована `node --check`, отдельным исполнением алгоритма в Node и DOM-ориентированным тестом, готовым к запуску в окружении с Playwright.

## Decision Log

- Decision: пользователь выбирает ровно два банка, без отдельного выбора уровней.
  Rationale: это соответствует задаче «банк против банка» и устраняет повторяющиеся действия.
  Date/Author: 2026-07-27 / Codex
- Decision: каждый уровень показывается ровно один раз.
  Rationale: повтор одного уровня как аналога нескольких уровней создаёт ложное ощущение эквивалентности и затрудняет сканирование страницы.
  Date/Author: 2026-07-27 / Codex
- Decision: сопоставлять только уровни с подтверждёнными числовыми диапазонами входа; разрешать пересечение диапазонов или ограниченно близкий порог, сохраняя порядок линейки.
  Rationale: алгоритм не должен изобретать банковские условия или переносить данные между уровнями.
  Date/Author: 2026-07-27 / Codex
- Decision: краткие карточки видны сразу, подробности раскрываются по запросу; предусмотрены команды «Развернуть все» и «Свернуть все».
  Rationale: полные тексты тринадцати категорий для всех пар одновременно делают страницу непригодной для быстрого просмотра.
  Date/Author: 2026-07-27 / Codex

Он строит карту всей продуктовой линейки, показывает каждый уровень ровно один раз, различает точные совпадения, пересечение диапазонов, ближайшие уровни и отсутствие прямого аналога. Каждая строка раскрывается в подробную сравнительную таблицу, предусмотрены массовое раскрытие/сворачивание и PDF.

Выполнено 89 тестов основного набора для лендинга и структурированных банковских данных; все прошли, один браузерный тест пропущен из-за отсутствия Playwright. JavaScript собранного HTML успешно прошёл `node --check`. Команда `--build-sber-vs` создала HTML для 7 банков и 38 уровней; необязательное копирование в соседний каталог публикации не выполнено из-за ограничения доступа рабочего окружения.

## Context and Orientation

`landing/sber_vs.py` читает только `output/comparison_data.json`, готовит пользовательские значения и встраивает JSON, CSS и JavaScript в статический HTML. `build_payload()` уже сохраняет все уровни каждого банка и вычисляет `entry_match` — подтверждённый числовой диапазон условия входа. Встроенный JavaScript сейчас хранит три выбора вида «банк + уровень» и строит одну таблицу из трёх уровней. Изменение заменит этот интерфейс на два выбора банка и несколько независимых сравнительных карточек.

Функции структурированной оценки и подсветки победителей остаются источником визуального ранжирования внутри каждой пары. Банковские значения, provenance и правила разрешения конфликтов не меняются.

## Plan of Work

В `landing/sber_vs.py` изменить текст и разметку `render_html()`: оставить два селектора банка, заменить рекомендации и единственную таблицу контейнером карты уровней, добавить управляющие кнопки раскрытия и PDF.

Во встроенном JavaScript хранить два индекса банков. После выбора обоих банков выполнить выравнивание последовательностей уровней динамическим программированием. Допустимой парой считать два подтверждённых диапазона, которые пересекаются либо находятся достаточно близко относительно своего масштаба. Цена пропуска позволяет оставить уровень без аналога; обратный проход гарантирует, что каждый уровень попадёт ровно в одну строку и порядок банковских линеек не изменится.

Каждую строку отрисовать элементом `details`. В заголовке показать банк, уровень, условие входа и качество сопоставления. Внутри построить существующие категории в двух колонках, вызвать существующую структурированную подсветку для настоящих пар, а для одиночного уровня явно написать, что прямого аналога нет.

В `tests/test_sber_vs_alignment.py` заменить сценарии выбора трёх уровней проверками двух банков, уникальности уровней, статусов сопоставления, раскрытия карточек, выравнивания колонок и отсутствия горизонтального переполнения на мобильном экране.

## Validation and Acceptance

До выбора двух разных банков карта скрыта и отображается понятная подсказка. После выбора появляются все уровни обоих банков. В DOM каждый `tier_id` выбранных банков встречается в заголовках карточек ровно один раз. Пары не нарушают исходный порядок уровней; неподтверждённые или слишком удалённые уровни отображаются как одиночные. При раскрытии пары видны все непустые категории и подсветка результатов. «Развернуть все» и «Свернуть все» меняют состояние всех карточек. На ширине 390 пикселей страница не имеет горизонтальной прокрутки. PDF-кнопка остаётся доступна.

## Idempotence and Recovery

Сборка статического HTML идемпотентна. Изменение не затрагивает JSON и банковские факты. Существующие незакоммиченные изменения в `landing/sber_vs.py` сохраняются; при конфликте редактируется только разметка, CSS и браузерная логика.
