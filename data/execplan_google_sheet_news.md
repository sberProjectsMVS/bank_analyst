# Подключить редакционные новости из Google Sheets

Этот ExecPlan является живым документом и поддерживается по правилам `PLANS.md`. Разделы `Progress`, `Surprises & Discoveries`, `Decision Log` и `Outcomes & Retrospective` обновляются по мере выполнения.

## Purpose / Big Picture

Коллеги заполняют одну Google-таблицу с четырьмя колонками: банк, дата, новость и ссылка на источник. При сборке раздела «Последние изменения» скрипт автоматически загружает опубликованные строки таблицы, строго проверяет их, сохраняет последнюю корректную копию и объединяет с новостями PremiumBanking.info. На сайте обе группы новостей выглядят одинаково: заголовок банка, месяц и год, текст новости и ссылка «Источник».

## Surprises & Discoveries

- Observation: Google Drive подключён, нативная таблица создана и проверена через Sheets API.
  Evidence: spreadsheet id `189w5qRBPq3_imP3XBwSJaXElnj-_ZzETzg_GFTPZEnA`, листы `Новости` и `Инструкция`.
- Observation: runtime проекта имеет только `requests`, `beautifulsoup4` и `openpyxl`.
  Evidence: `requirements.txt` не содержит Google OAuth-библиотек. Поэтому синхронизация будет использовать CSV export URL таблицы без новых зависимостей.
- Observation: раздел изменений сейчас всегда подменяет URL новости официальной страницей банка.
  Evidence: `_source_button_url()` выбирает `SOURCE_BUTTON_URLS[bank]` раньше `sourcePage`; для редакционной строки необходимо сохранить конкретную ссылку из таблицы.
- Observation: созданная таблица приватная, поэтому Python-процесс без Google OAuth получает HTTP 401 на CSV export.
  Evidence: запрос настроенного `export?format=csv` вернул 401. Для выбранной схемы без OAuth владелец должен включить доступ «Все, у кого есть ссылка — читатель».
- Observation: Google CSV export иногда обрывает chunked-ответ.
  Evidence: несколько запросов завершились `InvalidChunkLength`; загрузчик теперь делает до трёх попыток и при исчерпании использует последний корректный кэш.
- Observation: числовое значение `27` в колонке даты Google трактует как дату 1900 года.
  Evidence: CSV вернул `1900-01-26`. Добавлены проверка диапазона дат в таблице и серверная граница 2000…следующий год.

## Decision Log

- Decision: пользовательские колонки таблицы — `Банк`, `Дата`, `Новость`, `Источник`.
  Rationale: это точный минимальный формат, согласованный с пользователем.
  Date/Author: 2026-07-27 / Codex

  Rationale: текущий Python-парсер сможет читать таблицу при каждом запуске без OAuth-зависимостей и без фронтового ввода.
  Date/Author: 2026-07-27 / Codex
- Decision: импорт файла атомарный.
  Rationale: если одна непустая строка некорректна, новая версия таблицы целиком не заменяет последний проверенный кэш; сайт продолжает использовать прежние корректные данные.
  Date/Author: 2026-07-27 / Codex
- Decision: конкретный URL источника обязателен и показывается ссылкой «Источник».
  Rationale: Google Sheet является редакционным каналом, но не первичным подтверждением банковского факта.
  Date/Author: 2026-07-27 / Codex

## Context and Orientation

`landing/premium_changes.py` получает обновления PremiumBanking.info и генерирует самостоятельный `output/premium_changes.html`; тот же компонент встраивается в `output/sber_vs_banks.html`. `main.py --build-premium-changes` запускает сборку отдельной страницы, а `--build-sber-vs` косвенно вызывает `load_changes()`.

Новый модуль `scanner/editorial_news.py` будет отвечать только за Google Sheets: читать конфигурацию, загружать CSV, нормализовать строки, проверять банк/дату/новость/URL, устранять полные дубликаты и атомарно сохранять `data/editorial_premium_news.json`. При сетевой ошибке сборка использует последний успешный кэш. Ошибка содержимого таблицы видна в CLI и не портит кэш.

CSV URL сначала берётся из `PREMIUM_NEWS_SHEET_CSV_URL`, затем из `data/premium_news_sheet.json`. Парсер принимает точные русские заголовки, игнорирует полностью пустые строки и требует все четыре значения. Дата принимает ISO `YYYY-MM-DD`, `DD.MM.YYYY` и типичные варианты CSV; для сайта сохраняются `dateSort`, русская подпись месяца, конкретный источник и происхождение `google_sheets`.

В `landing/premium_changes.py` объединить новости PBI и редакционные записи. Редакционные URL не заменять общей банковской страницей. При отсутствии конфигурации поведение остаётся прежним.

В `main.py` добавить `--sync-premium-news`. Команды сборки автоматически пытаются синхронизировать таблицу и безопасно используют кэш при сетевой ошибке.

## Validation and Acceptance

Корректная таблица с одной строкой Сбера создаёт одну редакционную новость, которая появляется рядом с PBI и сохраняет прямой URL. Повторная строка не дублируется. Пустое обязательное поле, неизвестный банк, некорректная дата или URL отклоняют всю новую выгрузку и не перезаписывают кэш. Сетевая ошибка использует последний успешный кэш. Без настроенного URL существующие команды работают как раньше.

## Idempotence and Recovery

Повторная синхронизация одной таблицы даёт тот же JSON. Кэш записывается через временный файл и атомарную замену. Для восстановления достаточно исправить Google Sheet и повторить `--sync-premium-news`; последняя корректная версия сохраняется до успешной синхронизации.
